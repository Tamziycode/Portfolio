// Backend API — Concurrency
Library Management API

Enterprise REST API for library inventory and patron lifecycle. Architecture prioritises data integrity over convenience.

  • Pessimistic locking on borrow transactions — concurrent requests for the last copy cannot both succeed; one blocks until the first commits planned: Spring Data JPA migration
  • JWT RBAC with distinct permission scopes — admin (inventory write) vs patron (borrow/view) enforced at middleware, not controller logic
  • Paginated, cursor-aware REST endpoints with indexed filtering — response times stay predictable as catalogue scales
  • Transactional rollback on partial borrow failures — inventory count never decrements without a matching borrow record
